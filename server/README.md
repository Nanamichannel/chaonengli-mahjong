# 服务器数据库层（联机用）

这一层解决的问题：**四个人同时打一局牌，服务器要把"谁手里有什么、牌山下一张是什么、该谁打、分数多少"记清楚，而且不能让别人看到你的手牌。**

现在它是一个独立的 SQLite 数据库 + 一层 Python 访问代码，**不需要安装任何东西**（Python 自带 sqlite3）。

---

## 1. 为什么是这个方案（可行性说明）

| 方案 | 行不行 | 说明 |
|---|---|---|
| Godot 里直接连 SQLite | ✗ | Godot 没有内置数据库，要装第三方插件（GDExtension），插件还要和引擎版本严格对应，容易坏 |
| 用 C# 写（项目是 Mono 版） | ✗ | 这台电脑**没装 .NET SDK**，C# 现在编译不了 |
| **Python + SQLite** | ✓ | 电脑上已有 Python 3.10，`sqlite3` 是自带的；一个文件就是一个数据库，零安装、零维护 |

所以：**数据库层用 Python 写**。

更重要的是，联机麻将必须有一个"权威服务器"——所有判定（能不能吃、是不是诈和、胡多少番）都由服务器算，客户端只负责显示和把玩家的操作发上去。客户端说"我胡了"是不算数的。这场"服务器"将来就是跑这套数据库层的那一边。

## 3. 数据库里存了什么（按规则推出来的）

### 3.1 人和房间（联机要先能凑齐 4 个人）
| 表 | 存什么 |
|---|---|
| `users` | 账号、昵称、天梯分、胜场 |
| `sessions` | 登录 token → **断线重连**就靠它 |
| `rooms` / `room_seats` | 邀请码、房间状态（等待/进行中/结束）、4 个座位、准备状态 |

### 3.2 对局与每一局
| 表 | 存什么 |
|---|---|
| `matches` / `match_seats` | 一场对局、4 家的东南西北、当前分数、是否掉线 |
| `rounds` | 每一局：**场风（东/南）、局数、本场、亲家、立直棒、杠的次数、现在轮到谁、还剩几张可摸**、结算结果（自摸/荣和/流局/九种九牌）、番数符数点数、役种明细 |

### 3.3 牌桌本身（**核心，也是防作弊的重点**）
| 表 | 存什么 | 谁能看 |
|---|---|---|
| `round_wall` | **整副牌山的顺序**（136 张，含 14 张王牌）、摸牌序号、发给了谁 | **只有服务器** |
| `round_hands` | **每家的手牌** | **只有服务器 + 本人** |
| `round_discards` | 牌河：谁打的、第几张、是不是摸切、是不是立直宣言牌（横置）、有没有被吃碰走 | 公开 |
| `round_melds` | 副露：吃/碰/明杠/暗杠/加杠、鸣了哪张、谁打的、**横置那张是第几张**（和你现在客户端摆放的规则一一对应） | 公开 |
| `round_riichi` | 谁立直了、一发还在不在 | 公开 |
| `round_dora` | 宝牌/里宝牌：指示牌 → 实际宝牌（含 9→1、东南西北、白发中循环），几张已翻开 | 翻开的才公开 |

**一张物理牌 = 一个唯一编号 `wall_seq`（0..135）。** 这一条很关键：一副牌里有四张"5m"，只有编号才能分清哪张在谁手里、哪张被打出了。

### 3.4 过程与账
| 表 | 存什么 |
|---|---|
| `round_actions` | **每一个动作的日志**（摸/打/吃/碰/杠/立直/和/过），用于复盘、断线重连补发、防作弊审计 |
| `score_events` | 分数流水（谁 +多少 / −多少、什么原因） |

## 4. 三条安全规则（写在代码注释里，别绕过）

1. **牌山顺序、别人的手牌，永远只留在服务器。**
   → 代码里分了三档查询：
   - `public_state(round_id)`：能发给所有人的（牌河、副露、宝牌、**手牌只给张数**）
   - `private_state(round_id, seat)`：公开信息 + **只有自己的手牌**
   - `server_state(round_id)`：完整牌山和四家手牌，**只给服务器自己用**
2. **每个动作一个事务**：写到一半崩了也不会留下半个状态。
3. **幂等**：客户端每个动作带一个 `client_action_id`；网络抖动重发同一个动作，服务器不会执行两次（自测第 10 项就验这个）。

## 5. 怎么用（服务器代码里）

```python
from db import DB

db = DB()                       # 默认 server/data/mahjong.db
db.init_schema()

uid = db.create_user("小明")
token = db.create_session(uid)          # 发给客户端，掉线重连时用它换回身份

room = db.create_room(uid)              # 返回 6 位邀请码
db.join_room(room["room_code"], uid2)
match_id = db.start_match(room["room_id"])          # 人齐开局
round_id = db.start_round(match_id, "dong", 1, honba=0, dealer_seat=0, seed=12345)

got = db.draw(round_id, seat=0)                     # 摸牌（返回摸到什么）
db.discard(round_id, seat=0)                        # 打刚摸的那张
db.meld(round_id, seat=1, kind="chi", tiles=["3p","4p","5p"],
        called_tile="3p", from_seat=0, from_discard_seq=7, rot_index=0)
db.discard(round_id, seat=1, riichi_tile=True)      # 立直宣言牌（横置 + 扣 1000）
db.finish_round(round_id, "tsumo", winner_seat=1, han=4, fu=40, points=8000)

db.public_state(round_id)                           # 广播给所有人
db.private_state(round_id, seat=2)                  # 单独发给 3 号位
db.replay(round_id)                                 # 复盘 / 重连补发
```

### 7.1 流程状态机（game.py）

一个回合：`draw`（服务器帮该家摸）→ `discard`（打牌/立直/自摸/杠）→ 有人打牌后开 `claim` 鸣牌窗口 → 没人鸣就下一家摸，有人鸣则鸣的那家出牌。

- **鸣牌优先级**：荣和 > 碰/杠 > 吃；同级按离放铳者的远近。多家荣和默认「头跳」（只取最近一家，可开关）。
- **窗口关闭**：能鸣的几家都表态（或有人荣和）就立刻结算。
- **服务器说了算**：`legal_actions(seat)` 告诉客户端有哪些可选动作，`act()` 会重新校验一遍，非法动作直接拒绝。
- **看到的和看不到的**：`state_for(seat)` 只把「公开信息 + 你自己的手牌」发给本人；牌山和别人的手牌永远不出服务器。

### 7.4 副露显示规格（客户端照着画）

**通用原则**：副露的牌 = 「谁的牌横置」表示从谁那里鸣的 —— 上家 0 / 对家 1 / 下家 2（`round_melds.rot_index` 就是它，
`-1` 表示没有横置的牌）。一组副露的牌紧贴在一起，第一组贴自己那一侧的角，之后的组接着往前排。

| 副露 | 显示 | 数据 |
|---|---|---|
| 吃 | 3 张，被吃那张横置 | `kind='chi'`，`tiles_json` 是显示顺序 |
| 碰 | 3 张，被碰那张横置 | `kind='pon'` |
| 明杠 | 4 张**全正面朝上**，横置那张摆第 2 张（杠上家/对家）或第 3 张（杠下家） | `kind='minkan'` |
| **暗杠** | **3 张图 = 4 张牌：外侧 2 张背面 + 中间 1 张正面图（图里自带 2 张牌）** | `kind='ankan'`，`rot_index=-1`（无横置） |
| 加杠 | 把原来那副**碰升级成 4 张**，横置位置和明杠一样 | `kind='kakan'`（数据库里那副碰已经变成 4 张） |

**「横置那张摆在从左往右第几张」**（`rot_index`，从 0 数）：

| 鸣的是谁 | 吃 / 碰（3 张） | 明杠 / 加杠（4 张） |
|---|---|---|
| 上家 B | 0（最左） | **1（第 2 张）** |
| 对家 C | 1（中间） | **1（第 2 张）** |
| 下家 D | 2（最右） | **2（第 3 张）** |

**门前清**：吃 / 碰 / 明杠 / 加杠都会破门清，**暗杠不破**。

**暗杠的正面图**放在 `Cailiao/.../默认风格 default style/槓 kan/`，命名是「数字重复两遍 + 花色」，
**一张图里就画着上下两张牌**（尺寸 360×569，每张是横躺的牌）：

- 3s 的杠 → `33s.png`；11z → `11z.png`（实测 33s.png 里是两张 3s 上下叠着）
- **5m / 5s / 5p 的杠不要用 `55m/55s/55p.png`，要用 `05m/05s/05p.png`**（赤 5 的版本）
- 数据库里的 `tiles_json` 存的是真实牌 id（含 `0s` 这种赤宝牌），客户端据此选图

**这张正面图的旋转**（要同时满足两件事：① 两张牌顺着副露排的方向 ② 牌面朝向符合该家的视角）：

| 谁 | 副露方向 | 旋转 | 结果 |
|---|---|---|---|
| 自己 | 横排 | **90°** | 两张牌左右并排、牌面竖着（和我其它副露一致） |
| 对家 C | 横排 | **270°** | 两张牌左右并排、牌面朝对面（倒过来） |
| 上家 B | 竖排 | **0°** | 两张牌上下叠着、牌面横躺（和 B 手牌一致） |
| 下家 D | 竖排 | **180°** | 两张牌上下叠着、牌面横躺且倒过来 |

> 注意：不能简单按 90/180/270 对四家统一 —— 上下家的副露是竖排的，图转 90° 会让两张牌变成左右并排，就串行了。

**暗杠的背面图**：

| 谁 | 用哪张 | 旋转 |
|---|---|---|
| 自己 | `背面 back/b_02.png` | 不转（原始） |
| 上下两家（B / D） | `背面 back/b_01.png` | 转 180° |

**排布细节**：
- 4 张**紧密相连**（不留缝），位置规则和普通副露一样（贴基线、贴自己那一侧的角）。
